# 商标注册证三项要素反查技能

面向任何接手的 AI：用户给一个商标注册号，产出三项数据，外加一段请用户拿实物证书回传校准的提问。全程输出纯文本编号列表，禁止使用表格（用户复制会错位）。

---

## 一、输入与输出

输入：一个商标注册号，通常是 8 位数字（如 90475554）。偶尔会给 15 位申请号，或 7 位的旧证号。

输出固定四项，按顺序给出：

1. PDF417 编码字符串（纯字符，无空格）
2. 证书票面左上角、PDF417 正下方那一行带星号的印刷小字
3. 二维码里存的网址
4. 一段核对提问（不是数据，是请用户回传实物值的句式，见第九节）

不生成、不交付二维码 PNG。用户若明确要图片才另做，默认不给。

---

## 二、先把"位置"说明白（最容易搞混的地方）

这一节必须先向使用者交代清楚，否则后面全部对不上。

**PDF417 在哪**：证书票面左上角那个扁长形、由多条横向细条堆叠成的二维条码。它的上沿通常还压着一小段日期戳。

**"小字"指哪一行**：就是 PDF417 正下方、紧贴条码下沿、两端各有一个星号包住的那一行印刷编码，形如 `*TMZC82682296D02T250906*`。它在纸质证书和电子注册证上都有，是印刷体，不是网页文字。

**最容易误认的替代物**：新门户网页公示页里，PDF417 下方也会渲染出一行两端带星号的串，形如 `*BHFS20240000165686ZCZC01*`。那是网页把 barCode 去掉开头 `B1021`、再砍掉末尾 5 位得到的**截断展示串**，不是证书小字。拿到这一串不能直接当第二项交付，必须按第六节的规则重算日期。

**二维码在哪**：证书左下角。它存的是一个网址。

**网页上的日期不算数**：公示页条码上方显示的日期是页面当天渲染时间（同一天打开不同证书都显示同一个日期），与证书内容无关，绝不能拿来当小字日期。

## 三、两个数据源

### 3.1 旧公示系统（历史库）

地址：`https://wsgs.sbj.cnipa.gov.cn:9443/tmpu/puInfoView/puMobileRe.html?regNum={注册号}`

服务端渲染，整条记录以 JSON 形式放在页面里 `input#fl` 的 value 上。必须用浏览器（或带移动端 UA）打开，脚本直连会 403。

能拿到：注册号、商标名称、申请人、类别、注册日、有效期、fileBarcode、printDate、fileType 等。

局限：2026 年前后的新证大量缺失，返回 `{"total":0,"rows":[]}` 是常态；页面还会显示类似"公示数据更新到 2026-09-03"的截止日。**这两件事只说明"这条不在旧库的截止日以内"，不等于"没有这张证"**——注册日晚于该截止日的新证，在旧库必然查不到。最容易被误判成结论的一步就在这里，务必不要凭旧库为空就下"无此证""号码段不属于注册证"这类判断。判无证前必须走完 3.2 节的新门户查询。

真实误判案例（已发生）：把本技能交给另一个 AI 后，它对 90475554（注册日 2026-09-28）和 88881568（注册日 2026-06-21）都回了"未查到数据，公示数据更新到 2026-09-03，total 0 rows 0，大概率还没下发注册证"。真相是两张证都在新门户：前者 1021 版本 01 序号 12 命中，后者版式码 1023 版本 01 序号 18 命中。这类回复属于流程没走完，不是数据不存在。

### 3.2 新门户（现行系统）

页面：`https://pub.sbj.cnipa.gov.cn/toas-pub-prod/portalui-pub-prod/registerNoticeMobile?regNum={注册号}&barCode={条码}`

页面内同源接口（无需额外票据）：

`/toas-pub-prod/pub-prod-api/pubnotice/web/pubInfo/mobile/getPubInfo/{注册号}/{条码}`

返回 JSON，`data: null` 表示这个"注册号 + 条码"组合不存在；有值时可取：

barCode、certValidInfo、printDate、regDate、endDate、extenEndDate、bizType、fileType、applyNo、intlCls、tmName、applyCnName、certValidFlag。

要点：

- 页面必须带 barCode 才能打开记录，只有 regNum 是打不开的。
- 按注册号批量列记录的接口（getPubInfoList 之类）要登录，返回 401，所以 barCode 必须先有。
- 必须在 pub 域名页面内做同源 fetch。在 wsgs 页里 fetch 这个相对路径会落到 WebSphere 的 404。
- 反向验证过：服务端对非浏览器的 HTTP 请求（含伪造 UA、curl_cffi 模拟 Chrome TLS 指纹）一律返回 406，带 `#ENCODED#` 前缀的挑战页。所以拿不到数据不是参数错，是没过 WAF，必须用真实浏览器会话。

## 四、条码（barCode）结构

`B` + 版式码 + 业务码 + 12 位编号 + 文件类型 + 版本位 + `000` + 2 位发文序号

- 版式码：`1021` 为主，**`1023`、`1011` 也真实存在**。88881568 这张证就是 `B1023…`，只按 1021 拼会全空（实测），这类号必须三种版式码轮一遍。
- 业务码：`TMZC`（注册证，绝大多数）、`BHFS`、`BFZC`（补发）、`TMZR`（转让）、`TMBG`（变更）、`TMXZ`（续展）。非 TMZC 时编号段可能不是注册号左补零，此时以接口返回的 barCode 为准，不要自己套格式。
- 12 位编号：注册证为注册号左补零到 12 位（如 90475554 → `00000090475554`）；变更、转让后重发的证书可能用 15 位申请号。
- 文件类型：`ZCZC` 为主。
- 版本位：`01`、`02`、`03`……代表这张证的**第几次打印**，与票面小字里的 `D0X` 一一对应：`ZCZC01` ↔ `D01T`，`ZCZC02` ↔ `D02T`。
- 末位两位是发文序号（01–30），**不可推导**，只能枚举。

拼接示例（90475554 第 1 版第 12 号）：`B1021TMZC00000090475554ZCZC0100012`

拼接示例（88881568，版式码 1023，第 1 版第 18 号）：`B1023TMZC00000088881568ZCZC0100018`

## 五、取数流程

第 1 步：旧库查一次，能拿到完整记录就取字段，同时记下 fileBarcode。

第 2 步：把 fileBarcode 送到新门户接口验证一次，取最新字段（旧库的 printDate 有时为空或滞后）。

第 3 步：旧库为空、barCode 也没有，直接进枚举。注意"新证在旧库查不到"是常态，不是异常，不要因此中断。

第 4 步：枚举。先按 1021 跑版本 01–02、序号 01–30；全空再换 1023、1011 各跑一遍，最后才扩到版本 03–09。别只试 01、02 两个版本就下结论——补打三次四次就是 03、04，漏掉就永远查不到。

第 5 步：命中后照接口字段取值，再按第六节生成小字日期。

枚举执行的工程细节（踩过坑，务必照做）：

- 在浏览器页面内做同源 fetch，一次并发 10–12 个，按序号分成 01–12、13–24、25–30 几个区间跑。
- 一次并发 30–90 个会把管道读超时（GAC pipe read timed out）；顺序循环 15 个也可能超时。
- 判定命中：响应里没有 `"data":null` 即命中，barCode 原样回填。
- 已实测命中位置（一个号通常只有一个位置有效，序号随机）：87280855 是 01/16；84730481 是 01/17；87752123 是 01/17；88678045 是 01/10；89290619 是 01/17；86281398 是 01/18；90449078 是 01/14；90475554 是 01/12；86001089 是 01/14；82682296 是版本 02 序号 17；83084921 是版本 02 序号 18；88881568 是版式码 1023 版本 01 序号 18。

## 六、第二项（小字）的生成规则

格式固定：`*{业务码}{注册号}D0{版本}T{YYMMDD}*`

业务码、注册号、版本位全部来自第四节的条码，只有日期需要推算。日期是这套技能唯一会出错的地方，按下面三档处理。

**第一档：2022–2024 年批次**

直接把 printDate 转成 YYMMDD 使用，不用减天数，实测基本吻合。

**第二档：2020–2021 年批次及更早**

printDate 常比票面晚 7–9 天。改用另一条路径：注册日 + 21 天，若落点是周六则提前到周五、周日则顺延到周一，再转 YYMMDD。

**第三档：2025 年之后（现行批次）**

默认 printDate **减 1 天**；少数情况减 3 天（减 3 时通常是落到了周五）。已累计 8 例样本：7 例 −1、1 例 −3，因此 −1 是主路，遇到 −3 不要当异常处理，只是个案。

**周一这个特例单独记**：printDate 落在周一时，−1 是周日、−3 是周五，两种都出现过，不能凭星期几硬判。遇到周一，先按 −1 给值，同时在提问里明说 −3 的可能，等用户拿实物回传定案（86001089、90475554、88881568 三条正是这种待定情形）。

**兜底判断**：printDate 与实物值差一个月以上时，说明这条公示记录是后发的证（如公示在次年），此时规则全部失效，一律以实物为准，并把该号作为例外样本记下来。

**一致性校验**：算出的日期若落在未来、或早于注册日，必定是取错了条码（版式码、版本位或业务码不对），回到第五节重新枚举，不要硬凑。

## 八、异常边界

- 接口 `certValidInfo` 若已是带连字符的完整日期（例如 `BHFS77706132D01T2025-12-24`），它是系统侧的日期口径，仍需按第六节换算成票面形式，两者不是同一个值。
- 注册号位数不足 8 位时，先确认是不是旧证号（7 位），不要左补零当成新号查。
- 1021 全版本全序号都空时不要急着报"无记录"，按第四节轮 1023、1011；88881568 就是这样才命中的。
- 两库、全版式、全枚举都无命中，只能如实报"当前系统无此记录"，并提示用户核对号码；不得给出推测值。
- 同一号码在旧库与新门户的 printDate 不一致时，以新门户为准。
- 用户拿实物回传的值与本技能算出的不一致，以实物为准，并把该号立刻追加进第六节样本，口径随之修订。

## 九、第四项：回传校准提问（照抄这个句式）

这一项不是数据，是每轮交付末尾必须附上的一段话，目的是让用户持续拿实物校正日期规则。要求：写明推导链（用了哪个 printDate、减了几天），给出当前样本统计，把"错了就回传"说清楚；周一这种两可情形必须点名两个候选值。

命中（算出的值与用户回传一致）时的写法，例如：

> `261110` 对了：系统 printDate 是 11-11，减 1 天正好是 11-10。现在 2025 年后的 8 个样本里 7 个是 −1、1 个是 −3，−1 这条规则站得住。

首次交付（还没有回传值）时的写法：

> 第 2 项按 printDate 2026-11-11 减 1 天推的。实物如果是 261111，回我一句，我把这条口径标定。

周一两可时的写法：

> 这条的 printDate 落在周一（2026-07-13）：按默认 −1 是 261012（周日），按 −3 是 261010（周五），两种都出现过。回传实物值，这一条就能把周一的规则定下来。

不一致时的写法：

> 实物 xxx 与推算的 xxx 差 N 天，已按实物为准，这条记为新的例外样本。

四种句式统一在交付末尾出现，且每次都要带上"当前 −1 / −3 各几例"的统计，方便下一次直接判断规则是否还成立。

## 十、为什么有的 AI 枚举很慢（给接手方的提醒）

枚举速度不取决于模型本身，取决于它有没有"页面内跑脚本"的能力。

**快的做法**：先让浏览器打开一次 `https://pub.sbj.cnipa.gov.cn/toas-pub-prod/portalui-pub-prod/registerNoticeMobile?regNum={注册号}`，然后在**这个页面内部**用 JS 对同源接口并发 fetch，一次 10–12 个，只判断响应里有没有 `"data":null`。不导航、不渲染、不解析 HTML，单次响应约 1KB，30 个组合十秒级跑完。

**慢的做法**：把每个候选条码当成独立网址去打开，靠截图或读文本判断。每次都要过一次页面的 JS 校验、渲染、OCR，再回模型决策，单次十几到几十秒，30–90 个组合就是半小时以上，还容易中断。

**关键限制（已实测）**：这个接口不能用手写 HTTP 直连。不带浏览器指纹直接请求页面或接口，服务端一律返回 406 Not Acceptable；先取 Cookie 再请求同样 406；用 curl_cffi 模拟 Chrome 的 TLS 指纹也还是 406（返回带 `#ENCODED#` 的挑战页）。所以只能借真实浏览器的会话，靠"页面内同源 fetch"走通。任何只能"开网址、读页面"的 Agent，天然就只能一个个试，这是工具层的事，与它用哪个模型无关。反过来，只要能驱动真实浏览器（桌面自动化、装了浏览器插件的 DSH、能跑页内 JS 的 App），就跟本地一样快。

**给慢一方的三条省法**：

一，别自己枚举，先向已有条码索引的一方要 barCode，拿到后只开一个网址即可。

二，必须枚举时按先验收窄：实测命中位置集中在版本 01 的序号 10–25（16、17、17、10、17、18、14、12、14、18），先试 12–20 这一段，命中率最高，再往两头扩；1021 全空再换 1023、1011。

三，一次并发 10–12 个、分区间跑，不要一个跑完再发下一个，也不要一次并发 30 个以上（会管道读超时）。

## 附录 A：可直接粘贴的枚举脚本

适用前提：执行方必须能在**目标页面内部**跑 JS（已验证 MIKA、本机浏览器自动化均属此类）。纯 HTTP 直连、只读页面文字的 Agent 用不了这段，会 406 或只能逐页试。

第 1 步，先打开 `https://pub.sbj.cnipa.gov.cn/toas-pub-prod/portalui-pub-prod/registerNoticeMobile?regNum={注册号}`，取得会话并留在该页面。

第 2 步，在**该页面**内执行下面整段（只改 `reg`），把返回的数组原样取回：

```js
(async () => {
  const reg = '90475554';                // 换成待查注册号
  const layouts = ['1021', '1023', '1011'];
  const jobs = [];
  for (const L of layouts)
    for (let v = 1; v <= 2; v++)         // 先只跑版本 01、02
      for (let i = 1; i <= 30; i++)
        jobs.push('B' + L + 'TMZC000000' + reg + 'ZCZC' + String(v).padStart(2, '0') + '000' + String(i).padStart(2, '0'));
  const hits = [];
  for (let k = 0; k < jobs.length; k += 10) {
    await Promise.all(jobs.slice(k, k + 10).map(async bc => {
      try {
        const t = await (await fetch('/toas-pub-prod/pub-prod-api/pubnotice/web/pubInfo/mobile/getPubInfo/' + reg + '/' + bc, { credentials: 'include' })).text();
        if (!t.includes('"data":null')) hits.push(bc);
      } catch (e) {}
    }));
  }
  return JSON.stringify(hits);
})()
```

返回 `["B1023TMZC00000088881568ZCZC0100018"]` 即命中（注意版式码可能是 1023）；返回 `[]` 则把 `v <= 2` 改成 `v <= 9` 再跑一轮。

三条纪律：并发保持 10，不要提到 30 以上；每轮必须换 `reg`，别复用上一轮结果；拉到命中数组后立刻取字段，不要拿条码再去猜日期。
